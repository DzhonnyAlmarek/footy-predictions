# Тестовая авторизация, отдельная от Supabase

Только ветка `deploy/yandex-cloud`. Никаких изменений в `main`, Vercel и базе `club-murashev`.

На данном этапе на тестовой площадке разрешены только:
- `/api/test/health` (проверка запуска без базы),
- `/test-login`, `/api/test/login`, `/api/test/logout`, `/api/test/session`,
- `/test-area` (доступ только с подписанной сессией).

Все остальные маршруты приложения и рабочие API заблокированы независимо от значения `DEPLOY_TARGET`. **Это не готовая миграция приложения к Neon.** В тестовом образе не должны появиться ни ключи, ни адрес рабочего Supabase.

## Переменные окружения (не коммитить значения)

`DEPLOY_TARGET=yandex-neon-test` — для тестовых обработчиков API.

`TEST_LOGIN` — отдельный тестовый логин, отличный от действующих участников.

`TEST_PASSWORD_SCRYPT` — строка `<salt-hex>:<scrypt-hex>`: hex-соль 16 байт, hex-хэш 64 байта (scryptSync, Node.js).

`TEST_AUTH_SECRET` — случайное значение не менее 32 символов; лучше 32 случайных байта в base64url. Только окружение Яндекса или менеджер секретов.

Генерация на локальном компьютере с Node.js (пароль вводится локально, нигде не публикуется):

```javascript
const { randomBytes, scryptSync } = require("node:crypto");
const { createInterface } = require("node:readline");
const rl = createInterface({ input: process.stdin, output: process.stdout });
rl.question("Отдельный тестовый пароль (ввод видим): ", (password) => {
  const salt = randomBytes(16);
  console.log("TEST_PASSWORD_SCRYPT=" + salt.toString("hex") + ":" + scryptSync(password, salt, 64).toString("hex"));
  console.log("TEST_AUTH_SECRET=" + randomBytes(32).toString("base64url"));
  rl.close();
});
```

Пароль следует задавать сильный, уникальный. Сессионный cookie: 4 часа, HMAC-SHA256, HttpOnly/Secure/SameSite=Strict. Здесь нет регистрации реальных участников, восстановления паролей, Neon Auth, доступа к прогнозам или административных операций.

## Ограничения перед внешним размещением

- Пока **не проверено**, собирается ли Docker-образ; реальный запуск не выполнялся.
- Для применения этой тестовой авторизации необходимо проверить сборку, переменные Next.js и запуск контейнера.
- Даже при действующей блокировке маршрутов не передавать секреты или адрес продовой БД.
- Перед открытием приложения необходим аудит всех server/client Supabase обращений, авторизации в каждом API, файлового хранилища, телеграм-уведомлений и пересчётов.
- Ветка намеренно возвращает 503 на главной и блокирует исходные страницы — текущий режим предназначен для проверки безопасного входа, а не для участников конкурса.
