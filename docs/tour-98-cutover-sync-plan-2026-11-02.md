## Условия до любых изменений
1. Подтвердить резервную копию Neon и возможность восстановления; отдельно сохранить baseline строк по затрагиваемым матчам.
2. Повторить read-only сверку непосредственно перед применением: статус/счёт матчей, все поля новых прогнозов, все поля начислений (включая decomposition points_* / reason / created_at).
3. Убедиться, что 20 записей начислений не появились в Neon с момента проверки; не применять начисления при расхождении пары match_id,user_id или любой суммы.
4. Проверить FK, триггеры, вычисление рейтинга, другие зависимые таблицы и максимальные ID. Учесть, что старый сайт пока может принимать записи.
5. Остановить на время операции конкурирующую синхронизацию; согласовать окно записи и откат.

## Транзакционный сценарий (план, не исполняемый скрипт)
- BEGIN ISOLATION LEVEL SERIALIZABLE; SET LOCAL statement_timeout='60s';
- Установить блокировки на точно затрагиваемые строки matches, проверить базовое состояние.
- Убедиться, что прогнозы source ID 1758–1762 и пары match_id,user_id отсутствуют; INSERT с полным набором колонок и неизменными исходными timestamp.
- UPDATE только matches.id IN (420,421,422,423) и только при ожидаемом прежнем статусе/scores. Не трогать 419.
- INSERT начислений с полными исходными полями и с НОВЫМИ уникальными ID, сохранив source IDs в защищённом локальном журнале соответствий. Никогда не делать ON CONFLICT DO NOTHING, скрывающий ошибку.
- Проверить ровно 5 новых прогнозов; ровно 4 изменённых матча; ровно 20 новых начислений, суммы по матчам 7/13/11/8.
- Проверить дубли по (match_id,user_id), совпадение полей и рейтинг; только затем COMMIT, иначе ROLLBACK.
- После commit проверить рейтинг и счётчики на Neon, а также рассмотреть актуальность источника на момент переключения.

## Принцип отката
- Любой сбой до COMMIT → ROLLBACK.
- Если сбой обнаружен после COMMIT: не удалять вручную без оценки зависимостей/новых записей; восстановление через точечную обратную транзакцию или тестируемый PITR-план по согласованию.
